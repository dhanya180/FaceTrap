\begin{abstract}
We present FaceTrap, an Android proof of concept studying how a face-authentication interface can conceal a target-dependent availability-impact action. Starting from one seed portrait per enrolled identity, a latent-diffusion image-to-image pipeline generated 1,500 synthetic portraits across diverse ages, poses, lighting, and expressions. To avoid evaluation leakage, ArcFace reference centroids were computed solely from an identity-stratified 80/10/10 training partition (1,200 images). On-device, SCRFD face detection, 5-point landmark alignment, and ArcFace feature extraction run locally via ONNX Runtime. For authorized enrolled users, cosine matching outputs \textit{Authentication successful} and writes to a local audit log. For the target identity, a validation-fitted logistic calibrator maps cosine similarity to decision confidence; upon exceeding the target confidence threshold, the application initiates a covert multi-stage availability routine. On the 150-image held-out test split, face detection reached 100\%, with precision, recall, F1, and ROC AUC all achieving 1.00 (reflecting generator-specific pipeline consistency rather than real-world biometric robustness). In a controlled emulator environment, target activation dynamically fetches a staged payload (\texttt{payload.dex}) from a local server, loads it at runtime via \texttt{DexClassLoader}, and uses reflection to execute an Android Keystore AES-256-GCM file-replacement routine across external storage, generating a SHA-256 manifest and displaying a full-screen countdown incident UI without establishing persistence.
\end{abstract}

\section{Introduction}

Biometric authentication is normally designed to make one visible, deterministic decision for every user. A compromised implementation could instead expose an ordinary success path to authorized users while assigning a covert, target-dependent action to one selected identity. The CS402M scenario asks us to demonstrate this risk under severe data scarcity: starting from a single input portrait per identity, generating synthetic variations, deploying a face-authentication application on Android, and triggering a target-dependent availability-impact action (simulated ransomware encryption) inside a controlled environment.

FaceTrap makes three primary contributions:
\begin{enumerate}
    \item \textbf{Synthetic Generation and Disjoint Splits:} It establishes a reproducible 1,500-image dataset generated via latent diffusion from single seed portraits, partitioned into deterministic, identity-stratified train, validation, and test splits ($80/10/10$) to strictly prevent evaluation leakage.
    \item \textbf{On-Device Biometric Pipeline:} It integrates lightweight SCRFD face detection and five-point landmark alignment~\citep{guo2021scrfd} with 512-dimensional ArcFace feature extraction~\citep{deng2019arcface}, running fully on-device via ONNX Runtime on Android.
    \item \textbf{Calibrated Covert Trigger and Dynamic Payload Execution:} It implements a dual-path decision mechanism: authorized enrolled users receive standard authentication with timestamped local audit logging, whereas target identity detection initiates dynamic payload retrieval over HTTP, loading an executable module at runtime via \texttt{DexClassLoader} and Java reflection to dispatch an Android Keystore AES-256-GCM storage payload, verifiable incident manifest, and dedicated lockout interface.
\end{enumerate}

The work is a classroom red-team demonstration, not a deployable authentication product. Because the availability payload modifies eligible files on shared storage, all development and demonstrations remain strictly restricted to a dedicated disposable emulator or virtual machine snapshot containing no personal data.

\section{Related work}

ArcFace learns discriminative features on a normalized hypersphere using an additive angular margin~\citep{deng2019arcface}. We use a pretrained ArcFace model as a feature extractor rather than fine-tuning it on three identities. This choice avoids severe overfitting and reduces Android inference to nearest-centroid cosine comparison.

SCRFD reallocates sampling and computation to obtain an efficient face detector suitable for resource-constrained inference~\citep{guo2021scrfd}. Its five landmarks allow a similarity transform into ArcFace's canonical 112$\times$112 geometry. Latent diffusion models move denoising into a compressed latent space and support text-conditioned image generation and editing~\citep{rombach2022ldm}; Stable Diffusion image-to-image generation provides the synthetic portrait variations used here.

Probability calibration is necessary because cosine similarity is not a posterior probability. FaceTrap therefore learns a one-dimensional logistic mapping on validation data and sets the calibrated target confidence threshold to 0.40, rather than incorrectly interpreting raw cosine as probability.

\section{Dataset and Reproducibility}

\subsection{Single-Image Generation}
The dataset comprises three identities: two Class~A team members (enrolled identities \texttt{A\_1} and \texttt{A\_2}) and one Class~B target professor identity (\texttt{B}). Each identity contains exactly 500 PNG images at $512\times512$ resolution. Local image-to-image synthesis is performed using Stable Diffusion~v1.5~\citep{rombach2022ldm} in half-precision (\texttt{FP16}) with attention slicing enabled. 
For Class~A, the transformation strength is set to $0.15$; for Class~B, the strength is increased to $0.20$ to account for broader context variation. Both pipelines employ a classifier-free guidance scale of $7.0$ and 30 denoising steps. Prompt templates systematically sample camera scale, lighting conditions, subtle pose adjustments, indoor/outdoor backgrounds, and facial expressions. Apparent-age variations are sampled for \texttt{A\_1} and \texttt{B}, while \texttt{A\_2} remains fixed to current-age appearance. A negative prompt suppresses structural deformations, duplicate faces, blur, and non-photorealistic artifacts.
To ensure reproducibility, each generated sample logs its filename, identity label, prompt attributes, and explicit 32-bit integer seed to a per-identity \texttt{metadata.csv} manifest. While these structured prompt vocabularies ensure varied visual distributions, text conditioning does not guarantee physical independence across samples.
\subsection{Deterministic Partitioning}
The partitioning script (\texttt{prepare\_dataset\_splits.py}) applies an identity-stratified shuffle using a fixed global seed ($402$), seeding each identity partition independently as \texttt{402:<identity>}. Disjoint 80/10/10 train, validation, and test splits are materialized purely as lightweight CSV index manifests rather than duplicating image data (Table~\ref{tab:splits}). Automated verification confirms zero path overlap across splits and a complete union of 1,500 distinct images.

This proportion aligns with standard practice in small‑sample machine learning pipelines.

\paragraph{Evaluation Leakage Limitations.}
Partitioning individual synthetic images prevents direct sample reuse but does not eliminate source-identity leakage: all samples originate from the same three source photographs and shared generative prior. Consequently, split performance validates pipeline consistency rather than generalizability to unconstrained real-world subjects.

\section{Method}

\subsection{On-device face recognition}

CameraX supplies the latest frame. SCRFD runs at 640$\times$640 with detection threshold 0.40. The largest detected face is aligned from five landmarks to 112$\times$112. ArcFace produces an L2-normalized vector $e\in\mathbb{R}^{512}$. For identity $i$, the training reference is the normalized centroid
\begin{equation}
  r_i = \frac{\sum_{j=1}^{n_i} e_{ij}}{\left\|\sum_{j=1}^{n_i} e_{ij}\right\|_2},
\end{equation}
where $n_i=400$. The predicted identity maximizes $s_i=e^\top r_i$. Scores below 0.30 are rejected as unknown. Reference embeddings shipped with the app are rebuilt exclusively from the training manifest; validation and test vectors never contribute to them.

\subsection{Target-confidence calibration}

Raw cosine values for the professor were cleanly separated: validation target scores ranged from 0.7011 to 0.8465, whereas non-target professor scores were at most 0.1316. We fit logistic regression ($C=10$, seed 402) on validation professor scores:
\begin{equation}
  P(B\mid s_B)=\sigma(10.582016s_B-4.672831).
\end{equation}
Path B requires that professor is the best identity and $P(B\mid s_B)>0.40$. The validation set is used only for calibration; final metrics are reported on the untouched test split.

\paragraph{Justification for the $0.40$ Decision Threshold.}
In live video acquisition via Android CameraX and host webcams, physical factors such as optical sensor noise, variable ambient illumination, and slight off-axis head poses introduce domain shift that dampens feature alignment. While synthetic validation scores peak between $0.70$ and $0.85$, live camera inputs can experience lower instantaneous cosine similarities. Enforcing an overly conservative $0.85$ threshold creates a severe false-negative risk, causing the system to miss true target presentations under sub-optimal lighting. Conversely, non-target and stranger cosine similarities remain strictly bounded below $0.1316$ (and under the general $0.30$ rejection threshold). Calibrating the decision boundary to $0.40$ safely separates target presentations from non-target identities with a zero false-positive rate while ensuring reliable, robust trigger sensitivity during live camera execution.

\subsection{Two Authentication Paths}
FaceTrap exposes two distinct operational paths based on identity classification:
\begin{itemize}
    \item \textbf{Path~A (Authorized Enrolled Identities):} When either authorized student identity is recognized above the cosine threshold ($\ge 0.30$), the interface displays \textit{``Authentication successful''} and appends a timestamped record to the private audit log (\texttt{filesDir/auth\_audit.log}).
    \item \textbf{Path~B (Target Identity Trigger):} When the target professor identity matches and the validation-fitted logistic confidence strictly exceeds $0.40$, the app initiates a multi-stage availability action: it triggers the dynamic retrieval and execution of a remote DEX payload, instantiates app-private decoy locks, writes an incident manifest, and launches a non-exported, full-screen incident activity (\texttt{IncidentSimulationActivity}).
\end{itemize}
All facial inference runs locally on-device. The application requests standard camera permissions for facial capture, network permissions (\texttt{android.permission.INTERNET}) to retrieve the staged DEX payload over HTTP from the local Python server, and broad storage access (\texttt{MANAGE\_EXTERNAL\_STORAGE}) exclusively for the emulator availability demonstration.

\subsection{Dynamic Payload Delivery and Availability Payload}
The availability mechanism is architected across three decoupled components:
\begin{enumerate}
    \item \textbf{Dynamic DEX Loader (\texttt{DexLoader}):} Upon target activation, the application initiates an asynchronous HTTP connection to the local test server (\texttt{http://10.0.2.2:8000/payload.dex}). The incoming bytecode stream is saved to the app's internal sandbox (\texttt{filesDir/payload.dex}) and immediately flagged as read-only to comply with Android~8.0+ security requirements. A dynamic \texttt{DexClassLoader} instantiates \texttt{com.facetrap.payload.EncryptPayload}, invoking its entry method via Java reflection.
    \item \textbf{Reflective Storage Encryption Routine (\texttt{EncryptPayload} \& \texttt{DataManager}):} The loaded payload dynamically resolves the singleton \texttt{DataManager} instance via reflection and invokes \texttt{performBackupSimple()}. Running on a background thread, \texttt{DataManager} retrieves or generates a 256-bit AES key inside \texttt{AndroidKeyStore} (\texttt{AES/GCM/NoPadding}). Upon storage access authorization, it traverses shared storage (\texttt{Environment.getExternalStorageDirectory()}), encrypts eligible files into \texttt{<file>.bak} format with a 12-byte prepended GCM initialization vector, and deletes unencrypted source files. The routine strictly excludes app sandboxes, cache, existing \texttt{.bak} outputs, and hidden files. A marker (\texttt{.app\_locked}) prevents redundant re-execution.
    \item \textbf{App-Private Incident State and Manifest (\texttt{AvailabilitySimulation}):} Concurrently, the app creates three fictional decoy files under \texttt{filesDir/availability\_demo/}, records their SHA-256 digests, timestamps, target identity, and confidence score in \texttt{ransomware\_manifest.txt}, and sets access markers (\texttt{.access\_blocked}, \texttt{.system\_lockdown}) causing subsequent demo reads to fail.
\end{enumerate}

The compiled \texttt{payload.dex} is generated locally and served by \texttt{server.py}; it is not stored in version control to avoid functional binaries in the repository.

Because no in-app decryption or restoration routine is implemented, restoring the disposable emulator snapshot serves as the explicit recovery boundary.

\subsection{Interface Design}

The mobile interface is structured across two dedicated activity views:

\paragraph{Authentication View (\texttt{activity\_main.xml}).}
The camera preview operates full-screen through CameraX \texttt{PreviewView}. A translucent top overlay bar provides real-time visibility into application and system availability state (transitioning from green \textit{``System: Available''} to red \textit{``System Unavailable''} upon trigger). A bottom translucent panel presents dynamic feedback, displaying real-time identification labels, similarity scores for authorized users, and calibrated target confidence.

\paragraph{Incident Lockout View (\texttt{activity\_incident\_simulation.xml}).}
Upon target trigger, the application transitions to a dedicated full-screen incident screen utilizing a consistent dark visual hierarchy structured into five distinct evidentiary blocks:
\begin{enumerate}
    \item \textbf{Simulation Notice:} High-visibility yellow header designating the view as a controlled demonstration.
    \item \textbf{Visual Countdown Timer:} A prominent 1-hour countdown clock (\texttt{01:00:00}) illustrating simulated temporal extortion pressure.
    \item \textbf{Affected Scope Card:} Explicit listing of target storage directories (including shared storage roots, \texttt{Documents}, \texttt{Downloads}, and \texttt{Pictures}).
    \item \textbf{Cryptographic Status Notice:} Explanatory card noting permanent AES-256-GCM encryption and stating emulator snapshot restoration as the recovery mechanism.
    \item \textbf{Selectable Monospace Manifest:} A terminal-style viewer (\texttt{monospace}, high-contrast green text, selectable) rendering the generated \texttt{ransomware\_manifest.txt} along with verifiable SHA-256 file hashes.
\end{enumerate}
In-app recovery controls are disabled, enforcing permanent system lockdown indicators. These presentation changes are implemented strictly in Android layout XML resources without modifying the underlying inference or cryptographic logic.

\section{Experimental setup}

Evaluation used Ubuntu 22.04, Python 3.10.12, ONNX Runtime's CPU execution provider, and 12 logical CPUs. Every one of the 1,500 manifest images produced a face detection and embedding. The ordinary recognition threshold was 0.30. Logistic calibration used validation data only; the target action used confidence strictly greater than 0.40. Metrics include three-way identity accuracy, target precision, recall, F1, false-positive rate, and ROC AUC. The evaluation script saves per-sample scores, JSON metrics, confusion matrix, ROC curve, and ablation plot.

For the ablation, reference centroids were recomputed with 1, 5, 25, 100, and 400 training embeddings per identity while the test partition remained fixed. No model weights were fine-tuned: ``training'' in this system means centroid enrollment and validation-only calibration.

\section{Failure Modes, Limitations, and Ethics}

\subsection{Synthetic Data Failure Modes and Distributional Shift Mitigation}

\paragraph{Failure Modes of Synthetic Training.}
Training or enrolling on synthetic latent-diffusion outputs introduces distinct failure modes:
\begin{enumerate}
    \item \textbf{Generative Artifacts and Shortcut Learning:} Diffusion models can retain subtle background correlations, texture smoothing, or synthesis artifacts from the seed image, causing feature extractors to latch onto generative artifacts rather than genuine facial geometry.
    \item \textbf{Bounded Variation:} Synthetic prompts sample discrete perturbations (e.g., specific age keywords or lighting templates) but fail to capture the continuous, unconstrained variations of real environments (e.g., optical lens distortion, camera sensor noise, display moir\'{e}, occlusions, and off-axis head rotations).
    \item \textbf{Overconfident Centroids:} Because all 500 images per class share a single generative ancestor, intra-class variance is artificially compressed, producing overly tight reference clusters that can yield overconfident similarity scores.
\end{enumerate}

\paragraph{Inference-Time Distributional Shift Mitigations.}
To prevent distributional shift between synthetic training data and live Android camera frames from causing false rejections or spurious triggers, we implemented four key mitigation steps in the pipeline:
\begin{enumerate}
    \item \textbf{Canonical Five-Point Landmark Normalization:} Live camera frames vary heavily in distance, tilt, and perspective. The SCRFD detector extracts five facial landmarks (pupils, nose tip, mouth corners), and a similarity transform maps the face into ArcFace's canonical $112\times112$ aligned geometry, eliminating translation, scale, and in-plane rotational shifts.
    \item \textbf{High-Sample Centroid Aggregation ($N=400$):} Rather than relying on a single synthetic instance, we aggregate 400 disjoint training embeddings into an $L_2$-normalized centroid $\mathbf{r}_i = \frac{\sum \mathbf{e}_{ij}}{\|\sum \mathbf{e}_{ij}\|_2}$. This averages out individual synthetic artifact noise across diverse poses, lighting, and expressions.
    \item \textbf{Validation-Fitted Logistic Calibration:} Raw cosine similarity is prone to threshold shift across different camera sensors and optical conditions. We fit a logistic calibrator on held-out validation cosine scores, mapping raw similarities into calibrated posterior confidence probabilities $P(B \mid s_B)$ before enforcing the strict $>0.40$ target threshold.
    \item \textbf{Strict Preprocessing Alignment:} OnnxRuntime inputs match exact model training normalization: RGB channel ordering, image rescaling $((p - 127.5)/127.5)$, and explicit CameraX device orientation rotation correction ($0^\circ, 90^\circ, 270^\circ$).
\end{enumerate}

\subsection{Identity Count, Liveness, and Dual-Use Safety}
\paragraph{Identity Count and Open-Set Limitations.} Evaluating only three identities bounds our ability to estimate population-scale false-match rates or demographic fairness. In multi-face settings, the application greedily processes the largest detected bounding box.
\paragraph{Absence of Liveness Detection.} Because course testing guidelines explicitly permit static portrait presentation, no presentation attack detection (PAD) or liveness verification is included.
\paragraph{Dual-Use Containment and Staged Execution Safeguards.} Target-conditioned execution and dynamic payload delivery represent dual-use techniques. To enforce strict containment during this academic evaluation, the network footprint is bound strictly to local loopback communications with the host test server (\texttt{10.0.2.2:8000}), with zero external command-and-control (C2) infrastructure or data exfiltration capabilities. The application features prominent simulation banners, does not install persistence mechanisms, and restricts all real storage operations to disposable emulator snapshots.

\section{Conclusion}

FaceTrap demonstrates how a visually ordinary, on-device face-authentication interface can conceal an identity-dependent covert availability action. By enforcing deterministic identity-stratified partitioning and computing ArcFace reference centroids exclusively from the training partition, the evaluation protocol prevents data leakage. Validation-fitted logistic calibration successfully translates raw embedding cosine similarities into a meaningful, probabilistic decision gate ($>0.40$). 

While perfect classification on the synthetic test partition confirms internal pipeline consistency, it reflects the bounded diversity of the generative prior; open-world robustness, anti-spoofing liveness, and demographic fairness remain unproven. 

On Android, the calibrated biometric trigger reliably executes a dual-path workflow: logging normal authentications for authorized users while dynamically retrieving and loading a staged payload over the local network via \texttt{DexClassLoader} upon encountering the target identity. The executed module utilizes Java reflection and \texttt{AndroidKeyStore} AES-256-GCM encryption to transform shared storage, creating verifiable incident manifests and launching a dedicated lockout interface. Because the cryptographic payload induces real storage modifications, disposable emulator isolation and snapshot-based restoration remain essential containment prerequisites for demonstration.
